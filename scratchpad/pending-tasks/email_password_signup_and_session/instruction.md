# Email/Password Signup and Session Creation with Appwrite

## Background
You are building the email/password authentication backbone for a SaaS application. Appwrite provides two complementary SDKs for this flow:

- **`node-appwrite`** (server SDK): used with an API key to administratively create user accounts via the Users service.
- **`appwrite`** (client-web SDK): used from end-user contexts to create authenticated sessions through the Account service.

Your job is to write a single Node.js script that exercises both SDKs against the same Appwrite project: it must first provision a brand-new user account (server-side, using the API key), then immediately log that user in (client-side, no API key) and print the resulting Appwrite session identifier so other tooling can pick it up.

## Requirements
- Implement a Node.js CLI script at `/home/user/myproject/index.js`.
- Read the Appwrite endpoint, project ID, and admin API key from the environment variables `APPWRITE_ENDPOINT`, `APPWRITE_PROJECT_ID`, and `APPWRITE_API_KEY`.
- Read the current `run-id` from the `ZEALT_RUN_ID` environment variable and build the user email as `harbor-${run-id}@example.com`. This run-scoped email keeps concurrent runs of the task isolated from each other.
- **Step 1 – Server-side signup:**
  - Use `node-appwrite`'s `Users` service configured with the admin API key.
  - Create a new user account whose user ID is generated by Appwrite's `ID.unique()` helper (no hardcoded user IDs).
  - Use a freshly generated random password of at least 8 characters (e.g., random alphanumeric).
- **Step 2 – Client-side session:**
  - Use the `appwrite` client-web SDK's `Account` service against the same endpoint and project. **Do not** attach the admin API key to this client.
  - Call `account.createEmailPasswordSession(email, password)` with the email and password from Step 1.
- **Step 3 – Output:**
  - Print the returned session's `$id` value as the **last non-empty line** of stdout, with no extra prefix or formatting on that line.
  - Exit with status `0` on success and a non-zero status on failure.

## Implementation Hints
- Both `node-appwrite` and `appwrite` are already installed inside `/home/user/myproject/node_modules`.
- The server SDK's `Users.create(...)` accepts a user ID, email, optional phone, and password (in that order). The phone argument may be left undefined for this task.
- The client SDK exposes `Client`, `Account`, and `ID`; build a new `Client` with `.setEndpoint(...).setProject(...)` (do **not** call `.setKey(...)` on the client SDK) and pass it to `new Account(client)`.
- Be careful to print only the session `$id` on the last line — log other diagnostics earlier or to `stderr` if needed. The verifier reads the last non-empty stdout line.
- Make the script safe to run repeatedly during development: catch and surface SDK errors via a non-zero exit code so the verifier can detect failures.

## Acceptance Criteria
- Project path: `/home/user/myproject`
- Command: `node /home/user/myproject/index.js`
- The script reads `APPWRITE_ENDPOINT`, `APPWRITE_PROJECT_ID`, `APPWRITE_API_KEY`, and `ZEALT_RUN_ID` from the environment.
- The user account it creates must have the email `harbor-${ZEALT_RUN_ID}@example.com`.
- The user ID passed to the server SDK's user-creation call must be generated via `ID.unique()` (no hardcoded literal user IDs).
- The script must call the client-web SDK's `account.createEmailPasswordSession(...)` (do not substitute another session method).
- Exit code: `0` on success.
- Stdout: the last non-empty line is the Appwrite session `$id`, a non-empty alphanumeric string matching `^[A-Za-z0-9]{8,}$`.
- Side effect: after running the script, the Appwrite project must contain a user account whose email equals `harbor-${ZEALT_RUN_ID}@example.com` (looked up via the server SDK).
