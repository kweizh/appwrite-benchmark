# Appwrite Storage: Create a Secure Uploads Bucket ## Background Appwrite Storage organizes files into buckets. Each bucket can enforce file size limits, allowed extensions, compression, encryption, virus scanning, and per-file or per-bucket permissions. Your team needs a hardened bucket called `secure-uploads` that only authenticated users can access, with a strict size/extension policy and storage-side protections enabled. You will write a Node.js script (using the official `node-appwrite` Server SDK) that creates this bucket against a real Appwrite project. The Appwrite endpoint, project ID, and API key are provided via environment variables. ## Requirements * Create a new Storage bucket using `storage.createBucket` with all of the following settings: * `permissions`: grant read AND write access to any signed-in user (use `Role.users()`). * `fileSecurity`: `true` (per-file permissions enabled). * `maximumFileSize`: `5242880` bytes (exactly 5 MiB). * `allowedFileExtensions`: `["jpg", "jpeg", "png", "webp"]` (order does not matter; values must be exactly these four). * `compression`: `"gzip"`. * `encryption`: `true`. * `antivirus`: `true`. * Use the bucket name `secure-uploads-${run-id}` (see `run-id` rules below). The bucket display name and the bucket ID must both incorporate the `run-id` suffix. * After creation, print the newly created bucket's ID to standard output as the LAST non-empty line, in the format: `BUCKET_ID: <bucket_id>`. ## Implementation Hints * Install/use the `node-appwrite` Server SDK. The SDK exposes `Client`, `Storage`, `ID`, `Permission`, and `Role`. * Read `APPWRITE_ENDPOINT`, `APPWRITE_PROJECT_ID`, and `APPWRITE_API_KEY` from environment variables to configure the client. * Read the current `run-id` from the `ZEALT_RUN_ID` environment variable and append it to the bucket name and ID so the task is safe to run concurrently. * Refer to the Appwrite docs: * https://appwrite.io/docs/references/cloud/server-nodejs/storage#createBucket * https://appwrite.io/docs/products/storage/buckets * The newer SDK style uses a single options object: `storage.createBucket({ bucketId, name, permissions, fileSecurity, maximumFileSize, allowedFileExtensions, compression, encryption, antivirus })`. ## Acceptance Criteria * Project path: /home/user/myproject * Entry point: a Node.js script that can be executed by the verifier. The verifier will invoke it with `node /home/user/myproject/index.js`. * The script reads `APPWRITE_ENDPOINT`, `APPWRITE_PROJECT_ID`, `APPWRITE_API_KEY`, and `ZEALT_RUN_ID` from environment variables. * When the script runs successfully, a Storage bucket exists in the configured Appwrite project whose ID matches the value the script printed to stdout. * The created bucket must satisfy ALL of: * `name` equals `secure-uploads-${run-id}` (where `run-id` is read from `ZEALT_RUN_ID`). * `fileSecurity` is `true`. * `maximumFileSize` equals `5242880`. * `allowedFileExtensions` is a set equal to `{"jpg", "jpeg", "png", "webp"}`. * `compression` equals `"gzip"`. * `encryption` is `true`. * `antivirus` is `true`. * `$permissions` contains both `read("users")` and `write("users")` (i.e., `Role.users()` for read and write). * The final non-empty line of stdout must match the pattern: `BUCKET_ID: <bucket_id>`.
